# MEMORY.md 只读注入与旧记忆退役

## 目标

保留维护者提供的 `MEMORY.md` 作为 bot 的背景资料。项目和工作区约束
（包括适用的 `AGENTS.md`）优先于这些资料。会话历史仍从消息数据库按权限查询。
退役旧记忆的自动学习、写入、整理和搜索分支，减少运行路径和维护成本。

此前 `OMB_LEGACY_MEMORY` 同时控制文件注入和旧记忆功能。现在只读注入独立运行，
旧环境变量不能重新启用自动学习或写入。

## 只读注入

保留现有的 `memory` 动态提示词段。单聊和群聊发出模型请求前读取本轮有权
使用的文件，提示词预览复用同一个读取和渲染逻辑。逻辑位置如下。

```text
system
  bot 身份 → 全局规则 → SOUL.md → … → 部门上下文
  → MEMORY.md（只读参考资料）→ 技能

本轮输入
  单聊请求 / 群聊窗口
```

提供方可以把动态段随本轮输入更新，具体传输沿用引擎现有接口。文件缺失或空白时
省略整段。沿用最多 200 行、24,000 UTF-8 字节以及过期条目过滤，文件读取本身也
设上限。提示词说明资料的用途和优先级，省去旧的写入指引、主题索引和近期工作简报。

单聊、群聊和预览的现有入口分别见 [server/index.ts](../../server/index.ts)。
读取和截断逻辑位于 [server/read-only-memory.ts](../../server/read-only-memory.ts)，动态段归类位于
[server/system-prompt.ts](../../server/system-prompt.ts)。

## 文件归属和访问范围

- 沿用 `SOUL.md` 的目录边界，将本地 bot 的注入源放在
  `<数据目录>/bots/<botId>/MEMORY.md`。维护者直接管理文件。运行时只读取允许路径中的
  普通文件，并拒绝通过符号链接获得额外路径的内容。
- 可信文件目录排除在 bot 的可写目录和文件授权之外。能够以服务进程同一身份执行
  任意命令的本机全权限模式，需要靠沙箱或操作系统权限落实这条边界。只读注入和文件权限
  分别验证。目录边界参考 [SOUL.md 的实现](../../server/bot-folder.ts)。
- 本地普通群聊按当前发言 bot 读取。共享工作区上下文保留现有受众边界，bot 的团队共享文件
  可进入各类有权访问的轮次，群专属文件限于对应群，成员私有层限于其私有会话。受限制的 Bot API 和来宾
  会话沿用当前关闭旧记忆时的数据范围。
  [受众规则](../../server/audience.ts) · [Bot API 提示词范围](../../server/bot-api-fence.ts)
- 由维护者明确选入现有 `workspaces/<botId>/MEMORY.md` 中要保留的内容。旧文件
  可能含自动学习内容或已失效的主题链接，升级时保留旧文件供查阅，可信注入源由人工建立。

## 删除范围

| 范围 | 调整 |
| --- | --- |
| 后台任务 | 删除自动召回、事实提取、群聊学习、记忆维护、夜间整理、dream，以及相关调度和待处理队列。 |
| 存储写入 | 删除自动建档、`MEMORY.md` 更新和自动提取的用户画像写入、主题文件、归档、每日 Markdown 流水、记忆变更日志和撤销写入。 |
| 工具和界面 | 删除 `memory_update`、`memory_log`、团队记忆提议、相关写入接口、设置面板、创建 bot 和分享时的旧记忆入口，以及可重新开启整套功能的旧开关。 |
| 搜索 | `session_search` 和侧栏搜索只查询有权访问的会话。删除旧记忆文件搜索和索引维护路径。原始消息、工具活动、附件引用和会话搜索索引继续保留。 |
| 导入和恢复 | 核对团队备份、模板、预设、工作区迁移、bot 归属迁移。旧字段按兼容数据解析，旧资料保留在原件或备份里，由维护者显式选入可信注入源。 |

备份还原与归属迁移原有的直接写入路径也纳入退役范围。
[团队备份](../../server/team-backup.ts) · [工作区备份](../../server/workspace-backup.ts)

删除运行链路与清理历史数据分开。首次升级保持现有旧文件和数据库可恢复。
旧记忆索引的物理清理可在确定备份及回退范围后另做迁移，聊天全文索引独立保留。

## 实施与验收

1. 先拆出只读文件来源和注入契约，接通单聊、群聊及预览。验证不同 bot 和受众只能看到
   自己有权使用的内容，并验证文件编辑后的下一轮能得到新版资料。
2. 删除旧运行逻辑，再清理工具目录、接口、配置、前后端 UI 及兼容分支。导入旧格式时
   验证资料仍可追溯，后台任务和文件写入保持停止。
3. 给新的提示词契约明确版本。旧原生会话在下次使用时从合法会话历史重建一次，
   继续排除旧记忆工具结果及可能携带旧记忆的压缩摘要。后续恢复沿用正常增量路径。
4. 按 [隔离验证流程](../verification/memory-layer.md) 检查实际引擎输入。覆盖空文件、超长
   UTF-8、旧会话续聊、受众隔离、无记忆写入、历史搜索和设置页。对验证文件、日志目录
   和记忆索引做前后核对。

会话历史的预算、摘要和恢复见 [单聊与群聊的会话上下文策略](context-compaction.md)。
