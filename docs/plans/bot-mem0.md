# 单人部署下的 Bot 长期记忆

状态为待实施。Maus 面向一个本地所有者。桌面、浏览器和手机可以是这个人的不同设备。**每个 bot 独立开启长期记忆，同一 bot 跨私聊线程共用一份记忆。** 设备配对、撤销和脚本权限继续由现有会话机制执行。[本地身份实现](../../server/person-key.ts) · [设备会话](../../server/sessions.ts)

## 分区与接入

| Mem0 字段 | 首版取值 | 生命周期 |
| --- | --- | --- |
| `user_id` | `maus-<environment-id>` | 沿用该部署已有的 Mem0 用户分区。换设备、重新配对或重启服务均使用同一个值。 |
| `agent_id` | Maus 持久化的 `bot.id` | 改名、换模型、切换私聊线程沿用原值。克隆 bot 或删除后重建会生成新 ID，默认关闭记忆。 |
| `run_id` | 省略 | 只保存长期记忆。线程 ID 留在 Maus 的对话记录中。 |

首版采用 NAS 已支持的固定角色凭据。为每个获准使用记忆的 bot 配置一个 profile，绑定上表两个 ID，关闭批量删除。Maus 保存工作区级端点和按 bot ID 绑定的凭据引用。每个 bot 首次开通需要在 NAS 配置一次 profile；之后可直接在 Maus 开关。这样可以复用现有 MCP 服务，也能由 NAS 拒绝越权读取。绑定校验用带预期 `userId` 和 `agentId` 的只读查询；仅通过握手或发现工具不足以证明凭据属于该 bot。[MCP 挂载入口](../../server/host/mcp-servers-host.ts) · [现有连接与凭据管理](../custom-mcp-servers.md)

## Bot 设置与调用

- 在 bot 设置中提供「长期记忆」开关，区分未配置、已关闭、已启用和连接失败。已有和新建 bot 默认关闭。所有者通过有配置权限的设备开通；聊天设备沿用其会话权限。模板和克隆只复制普通 bot 配置，专用凭据留在原绑定。界面按[项目设计规范](../../DESIGN.md)实施。
- 首版只在所有者直接发起的 bot 私聊挂载六项工具：查询、列表、按 ID 读取、新增、更新、删除。模型按当前请求调用。删除单条记录须按 ID 确认。群聊、搭档委派、Dots 外部工作端、定时任务和外部 API 轮次首版均不挂载私聊记忆。按入口和轮次判断，即使它们复用私聊线程也执行相同规则。
- 服务端从本轮实际执行的 bot 取得绑定，沿用 MCP 工具选择与审批。NAS 凭据保存在私有配置中；工具结果、聊天、日志和 bot 导出只保留非敏感信息。在工具执行和延迟批准时复核开关、bot ID 与本轮来源。关闭后撤销待执行调用，下轮移除工具；NAS 已经完成的写入保留。连接故障应允许继续聊天，禁用跨 bot 或旧共享凭据兜底。
- `memory-common` Skill 独立选配。首版工具验收在未安装 Skill 时执行。若后续提供 Skill，只给显式选中的 bot 启用。轮前自动 recall、轮后事实提取和后台整理继续保持退役。维护者提供的只读 `MEMORY.md` 与原话回查 `session_search` 沿用各自入口。[只读笔记](../memory.md) · [旧记忆退役范围](read-only-memory.md)

## 旧版切换

现有接入使用通用 MCP 连接 `mem0`，其 NAS 角色 `maus` 绑定 `agent_id=workspace`。2026-11-20 的部署记录显示 Pebble 随后明确关闭了该连接。切换时以当时的实际配置为准。

1. 识别并记录旧连接、绑定分区和 bot 的显式选择。保存可恢复的私有配置，区分同名的其他自定义服务。先停用已识别的旧共享连接，再开放按 bot 授权的工具，避免「继承全部 MCP」同时暴露旧分区。Pebble 保持关闭，其他 bot 由所有者逐个开通。
2. 旧 `workspace` 分区留存。记录缺少可信 bot 归属；如需迁移，由所有者指定记录和目标 bot。复制后按 ID 和内容核对，记录源与目标 ID 以便重试。正常切换与回滚均不清空远端记忆。
3. 换机恢复须核对部署标识、bot ID 和凭据归属。新部署或克隆缺少匹配绑定时显示未配置。回滚先关闭新入口，保留原配置供所有者恢复；Pebble 的关闭选择同样适用于回滚。

## 实施顺序与通过条件

| 阶段 | 交付 | 隔离验收 |
| --- | --- | --- |
| 1. 服务端分区 | 私有凭据绑定、分区校验、按轮次挂载、删除确认 | 临时 Maus 和测试 MCP 中建 A、B 两个 bot。A 写入标记，在另一设备的 A 新线程搜索命中并按 ID 读取。B 的搜索和列表查不到，持 A 的 ID 读、改、删均失败。故意互换凭据必须在启用前失败。 |
| 2. Bot 开关 | bot 设置、权限校验、错误状态、运行中撤权 | 仅开启 A，核对发给引擎的工具。关闭 A 后已排队审批失效，重开仍能读取旧标记。改名、重启后归属一致；新建、克隆、群聊和委派均无私聊记忆工具。固定模型只回复文本时，前后台的 Mem0 工具调用数均为零。 |
| 3. 切换与恢复 | 兼容旧配置、停用继承路径、运维说明 | 夹具预置共享凭据、旧记录、继承全部 MCP 的 bot 和显式关闭的 Pebble。升级、重复启动和回滚后检查每个 bot 的实际工具、旧记录和授权；再验证撤销设备、NAS 离线、缺少凭据、同标识恢复和异部署导入。 |

按[隔离验收约定](../verification/README.md)保存工具清单、对话结果与前后状态。此前直连 NAS 的验收证明了 MCP 传输和六项工具可用，上表的逐 bot 隔离仍待实现和验证。
