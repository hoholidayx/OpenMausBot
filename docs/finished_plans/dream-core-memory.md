# Dream 提炼陪伴与派活的核心记忆

2026-11-20 已实现并完成隔离验证。单用户模式下，每个 bot 有一份 `MEMORY.md`。Dream 按批读这个 bot 的聊天记录，结合它的职责，用工具逐条更新文件。写入成功即发布，下轮聊天自动读到。平时由 bot 自己整理，用户需要纠正时才打开管理界面。

## 核心记忆和 Mem0 各管什么

| 使用场景 | 读写方式 |
| --- | --- |
| 每次聊天都值得知道的相处偏好、长期分工 | 放在当前 bot 的 `MEMORY.md`。普通聊天只读；后台 Dream 和条目管理界面可以写。沿用现有单聊和普通群聊的注入范围，当前用户要求和项目规则优先。 |
| 用户让 bot 记下一件事，以后按需查找 | 日常聊天沿用 Mem0 工具。长记录和具体细节留给 Mem0。Dream 不调用 Mem0，也不把核心条目的变更同步过去。 |
| 某次聊天的原话、正在进行的任务 | 沿用会话搜索和委派状态。核心条目只写下次仍适用的一句话。 |

例如，“以后派设计单默认找 A”适合进入核心记忆。“这单今天先找 B”只影响本次派活。日常模型只有 Mem0 一种记忆写工具，不需要在两个写入目标之间做选择。[现有记忆入口](../memory.md)

## 一次整理怎样运行

1. **取下一批。** 按现有会话归属读取该 bot 的聊天正文，保留说话人和消息顺序。首次从已有历史开始，之后从上次处理位置继续。每 bot 只保存一个进度游标，采用稳定分页顺序，时间相同的消息也能分开。每批按模型输入预算截取，长消息可分段续读。沿用单用户服务已有的会话读取方式，无需给每条消息补设备身份、证据或标签。
2. **按职责判断。** 输入只有 bot 的角色说明（含 SOUL）、生效的 Dream 提示词、当前核心条目和这批聊天。服务空闲时处理，有积压就接着跑下一批；没有新消息就不调用模型。普通聊天优先。同一个 bot 同时只跑一批。
3. **逐条生效。** 后台模型通过下表的条目工具完成整理，也可以直接结束。批次成功结束才推进游标，包括零改动的批次。中断后从原位置重读，并把最新条目交给模型；已经落实的改动直接跳过。这样首次整理能逐步消化旧记录，重启也能续上。

## 条目工具和管理界面

`<数据目录>/bots/<botId>/MEMORY.md` 就是核心记忆。新条目使用普通 Markdown 列表，一条一句。当前条目随 Dream 输入一并提供，写工具由宿主绑定到正在整理的 bot。

| Dream 工具 | 一次调用的效果 |
| --- | --- |
| `core_add(text)` | 增加一条。已有相同条目时跳过。 |
| `core_update(oldText, text)` | 用当前完整条目定位，只替换这一条。 |
| `core_remove(oldText)` | 删除这一条已失效或重复的记忆。 |

复用旧 Maus 的唯一匹配和局部替换逻辑，匹配单位收紧到完整条目。更新或删除遇到旧文已变、匹配不唯一时，工具返回最新条目供重判。服务端串行处理同一 bot 的条目变更，基于最新文件原子保存；其余条目、手写标题和段落保持原样。工具不接收文件路径或整篇 Markdown。[旧版条目更新](https://github.com/hoholidayx/OpenMausBot/blob/a950e396926d489d69bcfc2add3c93ce25dc3219/server/workspace.ts)

每个 bot 的上限为 **200 条或 40,000 个 UTF-8 字节，先到为准**。条数按记忆条目计，字节数按保存后的整份 Markdown 计，包含标题、列表标记和换行。Dream 和 CRUD 都按修改后的结果检查：正好达到上限可以保存，新增或编辑导致任一上限被突破时跳过此次写入。已有超限文件保留原文，允许逐条缩减。常驻注入与预览使用同一口径。测试用带手写标题的 200 条记忆填满 40,000 字节，确认最后一条也能完整读到。[当前读取逻辑](../../server/read-only-memory.ts)

在 bot 设置里保留简单的条目列表，支持查看、新增、编辑、删除，和 Dream 共用同一组条目操作。日常整理不等待用户确认。聊天里的常驻段标明“此 bot 的核心记忆”，与文件可由 Dream 自动维护的实际行为一致。

## 可按 bot 调整的默认提示词

~~~text
结合你的职责，读这批聊天和已有核心记忆。
为了下次陪伴得更自然，或派活时少问一次，有哪件事值得一直记住？

只记用户自己表达、下次仍适用的习惯、偏好和分工，每条一句。助手的建议不算用户的约定。
保留“这个项目”等范围。同一句里的临时安排只管当次，“我通常……”才描述日常习惯。
先核对已有条目。用户后来描述的习惯有变化，就更新原条，只写当前事实。同义跳过，明确取消则删除。
复杂细节和任务进度留在原处。用工具逐条修改；没有值得改的就结束。
~~~

复用 bot 提示词面板的现有习惯，加一个“Dream 提炼准则”多行文本框，可编辑、保存、恢复默认。保存后从下一批起使用，无需重启，游标照常前进。例如陪伴 bot 可以补一句“优先记住我明确说过的相处方式”，派活 bot 可以补一句“优先保留跨任务反复适用的交付约定”。[提示词编辑约定](../finished_plans/bot-prompts.md)

## 落地与验收

先接通条目工具和 CRUD，再接入增量后台任务与提示词设置。旧 Maus 以 `a950e396926d489d69bcfc2add3c93ce25dc3219` 为参考，只取有界读取、结合当前笔记做纠正和逐条更新三部分。复用现有后台排队与用量记账；模型执行走能挂载工具的驱动入口，Dream 只挂载上述三个工具。现有后台纯文本调用本身没有工具接口。[旧 Dream](https://github.com/hoholidayx/OpenMausBot/blob/a950e396926d489d69bcfc2add3c93ce25dc3219/server/memory-dream.ts) · [后台任务](../../server/side-jobs.ts)

用隔离实例跑一条完整路径：给两个职责不同的 bot 放入多批聊天，验证各自自动更新自己的文件；新偏好新增、纠正只改一条、临时要求零改动。中途重启仍能处理后续消息，不重复添加已写条目。再从 UI 增删改各一条，核对下一轮实际提示词、其他手写内容及改提示词后下一批的行为。普通聊天看不到 Dream 工具，整理全程对假 Mem0 零调用。[隔离验证入口](../verification/README.md)

### 用聊天记录参考提炼效果（可选）

| 材料 | 挑哪些对话，观察什么 |
| --- | --- |
| WildChat-1M（真人与 ChatGPT 的对话，含中文） | 挑几段中文多轮对话，保留各自的会话边界。看 Dream 会不会把“这次回复短一点”一类临时要求写成长期偏好。不同会话分别回放，避免把不同人的发言拼成同一个人的习惯。[AllenAI 数据集卡](https://huggingface.co/datasets/allenai/WildChat-1M) |
| LongMemEval（人工设计问题、模拟关键会话的长期记忆测试集） | 从轻量的 `longmemeval_oracle.json` 挑 `single-session-preference` 和 `knowledge-update` 样本，按会话日期排序后分批送入 Dream。重点看旧偏好有没有被后来的纠正替换。参考答案只在回放后查看。[官方数据说明](https://github.com/xiaowu0162/LongMemEval) · [构造方法](https://arxiv.org/html/2410.10813v1) |
| Maus 派活样例 | 先用仓库已有的委派样例检查一次性任务有没有误入核心记忆。如果后续有愿意用于测试的真实 Maus 导出，可选几段连续聊天，脱敏后保留“这次”“这个项目”“以后”等限定词，再用于同样的回放。[仓库派活样例](../../evals/golden/samples/coordination-handoff.sample.json) |

调提示词时，让新旧版本在隔离实例里从相同的初始笔记回放同一批对话，并排看每批增、改、删了哪些条目。只记几个值得讨论的误记、漏记或正确更新的例子，供下次调整参考。样本量和分数均不作为发布门槛。


## 实施记录

Dream 复用现有后台槽位和用量记账。每个 bot 在消息库保存一个游标，按聊天写入时的快照分页，同一时间戳的消息按入库顺序处理。长消息按 Unicode 码点续读。前台聊天开始时，后台让出执行机会。OpenAI 兼容连接接收三个原生函数工具，命令行引擎通过隔离文本助手返回相同的条目调用，由宿主执行。

2026-11-20 用 Maus 现有的 OpenCode2Api 连接与 `deepseek-v4.1-flash` 验证了新增、纠正、撤销、按职责定制提示词和新会话读回。满 20 条和整份文件满 4,000 字节分别验证，真实模型都在收到容量反馈后删除了明确失效的条目，再次添加成功。自动化覆盖写入后中断、同数据重启、Mem0 隔离、桌面和手机上的条目维护。

公开样本回放保留了每个会话的边界。WildChat 的三轮中文技术咨询没有产生核心条目。LongMemEval 的健身时间用例第一次漏掉了后来的变化；调整默认提示词后，同一份输入将旧条目从晚上七点更新到六点。两次观察用于后续调整提示词。[验证记录与样本编号](../verification/memory-layer.md) · [使用说明](../memory.md)
