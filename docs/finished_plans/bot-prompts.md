# Bot 提示词清单与编辑范围

2026-11-18 核对了单聊、群聊和设置预览三条组装路径。已有的[上游 bot 文件夹设计](../archive/upstream-planning/superpowers/specs/2026-09-05-bot-folder-and-self-setup-design.md)解释了 SOUL 和预览的来历。[提示词预算测试](../../server/turn-prompt-budget.test.ts)按字节检查固定段和驱动开销。本清单关注实际正文、来源、作用范围及恢复行为。

## 在哪里查看

简单模式打开 bot 面板，点「提示词」。高级模式从「概览」或「Soul」打开同一个面板。桌面左侧列出各段，窄屏用下拉框切换。上半组编辑当前 bot，下半组按发送顺序展示当前配置生成的单聊提示词。预览里的 SOUL 可以看到正文外面的边界说明。每段的 token 按 UTF-8 字节数除以四向上取整，中文、代码及不同模型的实际分词会有差异。

## 可按 bot 编辑的字段

| 面板字段 | 默认正文来源 | 影响哪些回复 | 恢复默认值并保存后 |
| --- | --- | --- | --- |
| 模型系统前缀 | 当前模型连接中为该模型 ID 保存的全局前缀，默认可为空 | 该 bot 的常规 API 单聊和群聊。实际连接和模型都匹配时，前缀放在第一段 | 删除此 bot 对该连接和模型的覆盖，以后跟随模型默认值的更新 |
| 长期指令（SOUL） | `BotRecord.soul`，同步到该 bot 的 SOUL.md | 单聊和群聊。用户长期指令优先于记忆及导入的技能 | 清空长期指令。角色模板或创建时填入的初稿属于已有内容；需要找回旧稿时用 Soul 历史 |
| 人格 | `botPersona` 用当前名字、职位、简介生成单聊身份，默认 MausBot 还带有产品助手职责 | 自定义正文用于单聊和群聊。群聊另外提供说话人、房间名、成员和公告 | 单聊重新按当前资料生成。群聊重新使用自己的角色和简介 |
| 单聊回复风格 | 默认留空，可填写此 bot 的自定义正文 | 单聊。只影响提示词正文 | 清除此段，恢复默认回复行为 |
| 回复习惯 | `REPLY_HABITS_PROMPT`。包括长任务先说明、先给结论、结尾措辞、提问习惯、语言和失败时的说明 | 单聊和群聊都附加，即使 SOUL 为空也会出现 | 恢复当前版本的内置回复习惯 |
| 群聊回复风格 | `ROOM_REPLY_STYLE`，默认要求以自己的身份简短、自然地回复 | 该 bot 在房间里发言时生效。提及、回应和协作规则由房间另外提供 | 恢复群聊默认语气 |

按字段保存。SOUL、人格和风格等文本字段留空并保存可省略该段；「恢复默认值」再保存会删除覆盖，以后跟随内置文案更新。修改只影响后续组装的请求。已有 bot 无需迁移。SOUL 沿用原有文件镜像和历史；同时编辑同一字段时，服务端会核对读到的值再写入。

简单模式在 bot 的「详情」模型选择器旁打开「模型系统前缀」，高级模式在「模型」中打开，也可以从「提示词」进入。简单模式的模型入口对应当前会话使用的模型，包括会话固定的模型；高级模式的模型入口和通用「提示词」入口对应 bot 的默认模型。编辑器显示连接名称、模型 ID 和正文。

- **跟随模型默认值**会采用该连接中这个模型的最新前缀。默认正文为空时省略前缀。
- **对此 bot 关闭**会持续跳过注入，包括以后为模型添加或修改默认值的情况。
- **为此 bot 自定义**会用填写的正文完整替换默认前缀。切换模型或连接时，各自的设置会保留。「恢复默认值」并保存后，重新跟随模型设置。

前缀支持 OpenAI 兼容接口及其他使用原生聊天消息的 API 驱动。Claude Code、Codex、ACP 等代理驱动没有前缀入口。单聊使用会话选定的模型，简短消息也按该模型的配置注入前缀。

正文、段落排序与稳定／逐轮拆分见[组装器](../../server/system-prompt.ts)和[回复习惯原文](../../server/reply-habits.ts)。[可编辑字段](../../shared/bot-prompts.ts)与[写入逻辑](../../server/routes/bot-prompts.ts)定义了设置接口。

## 还有哪些内容会影响输出

| 来源或段落 | 何时进入上下文 | 维护位置 |
| --- | --- | --- |
| 全体规则、部门上下文、用户资料 | 分别由 `every-bot-rules`、`section-context`、`user-profile` 注入。团队环境还会带上当前人的资料 | 全局规则、部门、个人资料。它们的修改会影响该范围内的其他 bot |
| 记忆、技能与操作手册 | `memory` 读取相应的 MEMORY.md；`skills` 是索引，`skill-instructions`、`playbooks` 根据当轮任务选择 | 维护者文件、技能和手册。[记忆策略](../plans/read-only-memory.md) |
| 设置、任务和自动化 | `setup` 会要求先说明打算做什么，`just-do-it` 与权限模式相关；`routine`、`active-routines`、`routine-execution`、`automation-reply`、`webhook` 会改变操作与结果汇报方式 | [设置流程](../../server/setup-mode.ts)、[提示词组装](../../server/system-prompt.ts)和[请求分发](../../server/index.ts) |
| 电脑、工具与账号 | 文件位置、shell、电脑、当轮操作位置、浏览器、数据、邮箱、手机、已连接应用、MCP、停用工具、凭据和工具搜索会贡献各自的能力或使用说明 | bot 的访问设置、当前设备、工具授权。预览只列出当下产生正文的段落 |
| 团队和会话 | `coordination`、名册、在线状态、任务分配、待答问题、点名、等待和可检索的对话等依赖当前成员与任务。群聊还会添加公告、发言身份、交接说明 | 团队、房间、任务及当轮上下文。[会话上下文策略](../plans/context-compaction.md) |
| 驱动和工具结果 | 驱动会把稳定段和逐轮段交付给模型，也可能带上历史摘要、工具定义、工具返回的后续操作提示。供应商自己的系统指令由供应商管理 | [驱动拆分](../../server/drivers/prompt-split.ts)、各驱动和工具实现 |

面板中的单聊预览取自当前设置。历史某一轮实际发送了什么还取决于当时的模型、房间、设备、选中的技能和消息；查看历史用量时不能用今天的预览反推当时的正文。

## 验证

[隔离请求测试](../../server/bot-prompts.e2e.test.ts)用两个临时 bot 和回环模型接口核对发送的单聊、群聊正文，覆盖跨 bot 隔离、过期编辑、UTF-8 长度、留空和恢复。[模型前缀请求测试](../../server/model-system-prefixes.e2e.test.ts)覆盖实际请求的首段、跨 bot 和连接隔离、会话固定模型、旧 bot 的简短消息和重启持久化。界面可通过[机器人设置验证夹具](../verification/bot-settings.md)复核。
